0. 准备工作（必须先看 ⚠️）
====================================================================
0.1 服务器要求
  - CPU：≥ 1 核（推荐 2 核+）
  - 内存：≥ 1GB（推荐 2GB+）
  - 硬盘：≥ 20GB SSD
  - 系统：CentOS 7+ / Ubuntu 20.04+ / Debian 11+
  - 网络：能访问 Telegram 服务器（my.telegram.org、api.telegram.org）
    · 中国大陆服务器必须使用境外代理/中继；推荐选海外服务器
      （香港、新加坡、日本、美国等）

0.2 您需要准备的材料清单
  材料                            说明 & 获取方式
  ─────────────────────────────────────────────────────────
  (a) Telegram Bot Token          登录 TG → 找 @BotFather
                                  发送 /newbot 按提示创建，得到
                                  格式：123456789:ABC-DEF1234ghIkl-zyx57W2v1u123ew11
                                  【v1.0.2 可在后台填写】

  (b) 管理员 TG ID（个人 ID）     把任意一条消息转发给
                                  @userinfobot 或 @getidsbot，
                                  读取 from.id 数字
                                  【v1.0.2 可在后台填写】

  (c) Telethon api_id / api_hash  打开 https://my.telegram.org，
                                  用 TG 手机号登录 → API tools →
                                  Create new application，拿到
                                  一组 api_id（数字）和
                                  api_hash（32 位字母串）

  (d) 采集小号（至少 1 个，       带 +86 等国际区号的真实 TG
      推荐 3 个起）               注册手机号，密码可留空
                                  【v1.0.2 可在后台填手机号，

宝塔防火墙放行端口：
  宝塔 → 安全 → 放行：80、443、8001（临时调试用，配完 Nginx 可关掉 8001）
云服务商安全组也放行：80、443、8001

====================================================================

  · 创建 venv 虚拟环境到 ./venv

脚本跑完如果看到下面三行代表成功：
  ✅ Python venv + 依赖安装完成
  ✅ Systemd 服务 tg-search-bot 已创建

然后跳到【第 5 步 手写 .env 的安全项】。

4. 方式 B：手工一步步部署（老手 / 排错）
====================================================================
4.1 系统依赖
CentOS：
  $ yum install -y git gcc gcc-c++ make libffi-devel \
      zlib-devel bzip2-devel openssl-devel ncurses-devel \
      sqlite-devel readline-devel tk-devel gdbm-devel \
      xz-devel wget curl

Ubuntu/Debian：
  $ apt update && apt install -y git build-essential \
      libffi-dev zlib1g-dev libbz2-dev libssl-dev \
      libncurses5-dev libsqlite3-dev libreadline-dev \
      libgdbm-dev liblzma-dev wget curl

4.2 安装 Python 3.11（如果系统默认 < 3.10）
  $ python3 --version   # 若已 ≥ 3.10 可跳过本小节
  $ cd /tmp
  $ wget https://registry.npmmirror.com/-/binary/python/3.11.9/Python-3.11.9.tgz
  $ tar -xzf Python-3.11.9.tgz
  $ cd Python-3.11.9
  $ ./configure --prefix=/usr/local/python311 --enable-optimizations --with-ssl
  $ make -j$(nproc) && make altinstall
  $ ln -sf /usr/local/python311/bin/python3.11 /usr/local/bin/python3.11
  $ python3.11 -m pip install --upgrade pip -i \
      https://pypi.tuna.tsinghua.edu.cn/simple

4.3 创建虚拟环境 + 安装依赖
  $ cd /www/wwwroot/tg-search-bot
  $ python3.11 -m venv venv
  $ source venv/bin/activate
  (venv) $ pip install --upgrade pip setuptools wheel -i \
           https://pypi.tuna.tsinghua.edu.cn/simple
  (venv) $ pip install -r requirements.txt -i \
           https://pypi.tuna.tsinghua.edu.cn/simple
  # 验证安装（不应有 ModuleNotFoundError）：
  (venv) $ python -c "import fastapi, telethon, aiosqlite, jieba; print('✅ 依赖OK')"

4.4 创建目录 + 复制初始 .env
  $ mkdir -p data/sessions data/backups logs
  $ cp -n .env.production .env

4.5 创建 Systemd 服务（开机自启 + 守护进程）
  $ cat > /etc/systemd/system/tg-search-bot.service << 'EOF'
[Unit]
Description=TG Search Bot Service (v1.0.2)
After=network.target

[Service]
Type=simple
User=root
WorkingDirectory=/www/wwwroot/tg-search-bot
Environment="PYTHONUNBUFFERED=1"
ExecStart=/www/wwwroot/tg-search-bot/venv/bin/python -u main.py
Restart=always
RestartSec=5
StandardOutput=append:/www/wwwroot/tg-search-bot/logs/stdout.log
StandardError=append:/www/wwwroot/tg-search-bot/logs/stderr.log

[Install]
WantedBy=multi-user.target
EOF
  $ systemctl daemon-reload
  $ systemctl enable tg-search-bot   # 开机自启
  # 注意：⚠️ 先别 start，等第 5 步写好 .env、第 6 步登录完小号再启动

4.6 Nginx 模板（可选，第 9 步有详细）
  先不急，等系统跑通了再配 Nginx + HTTPS。

5. 手写 .env 的安全项（只有这部分需要改文件）
====================================================================
⚠️  v1.0.2 开始，除 HD 钱包助记词外，其他配置都可以在后台
    「⚙️ 系统配置」页面填写保存。这一步您只需要填
    HD_WALLET_MNEMONIC 即可。其他的留空没关系，进后台补。

编辑 .env：
  $ cd /www/wwwroot/tg-search-bot
  $ vim .env        # 或宝塔文件管理器可视化编辑 .env

================= 最少必填（仅 3 行左右） ======================
# ------ [🔐 安全硬约束] 下面这一行只能手写在 .env，绝对不能 ------
# ------ 在后台录入。写完立刻把助记词抄到纸 → 锁保险箱。 ------
HD_WALLET_MNEMONIC=单词1 单词2 单词3 单词4 单词5 单词6 单词7 单词8 单词9 单词10 单词11 单词12

# ------ [加密密钥] 首次部署生成一次固定，不要改，改了会 ------
# ------ 导致 DB 中加密配置读不出来。 -------------------------
# 如果想让 deploy 脚本帮您生成强随机，可先执行：
#   $ bash deploy/scripts/generate_secrets.sh
SESSION_SECRET=这里填 64 位以上随机字符串（字母数字混合）
CRYPTO_SECRET=这里填 64 位以上随机字符串（字母数字混合，不同于上面那条）

# ------ 其余 26 项全部可在后台填写 ------
# 您可以都留空，启动服务后登录后台 → ⚙️ 系统配置 → 填完保存。
====================================================================

⚠️  写完 .env 之后做三件事：
  ① 把 HD_WALLET_MNEMONIC 抄到纸上 → 对折 → 锁入保险箱。
  ② 删除终端里的历史（防止别人 grep 助记词）：
     $ history -c && rm -f ~/.bash_history
  ③ 退出 SSH 重登一次，防止终端 scrollback 被人看到。

6. 首次登录采集小号（输入短信验证码）
====================================================================
⚠️  必须在【启动 systemd 服务之前】完成！
    因为小号登录需要您交互式输入短信验证码、2FA 密码（如开了）。
    而后台 systemd 是无人值守的，没法让您打字。

进入 venv 并运行登录脚本：
  $ cd /www/wwwroot/tg-search-bot
  $ source venv/bin/activate
  (venv) $ bash deploy/scripts/login_accounts.sh

脚本会循环每一组 api_id/api_hash/手机号，让您做：
  ① 按 Enter 发送短信验证码
  ② 输入收到的 5 位数字短信验证码（如 12345）
  ③ 如果开了 2FA（二级密码），再输入二级密码
  ④ 显示 "会话写入成功: data/sessions/account_1.session" 即 OK
每个 session 文件对应一个小号，以后都不需要再登录
（除非 session 过期 / 换 IP 导致掉线）

登录完验证：
  (venv) $ ls -la data/sessions/
  应该能看到 account_1.session、account_2.session …

7. 启动服务并检查
====================================================================
7.1 先做最小自测（不通过 systemd，直接前台跑 main.py）
  $ cd /www/wwwroot/tg-search-bot
  $ source venv/bin/activate
  (venv) $ timeout 20 python main.py   # 20 秒无报错 Ctrl+C 结束
观察输出：
  · 不应有 ModuleNotFoundError → 缺依赖，回去 pip install
  · 不应有 ValueError: 配置校验失败 → 说明 .env / 后台配置都没填
    → 这是正常的（v1.0.2 可先启动，后台填完就 OK）
  · 不应有 "HD wallet derive failed" → 助记词写错/格式不对
看到 "Uvicorn running on http://127.0.0.1:8000" 代表启动成功，
按 Ctrl+C 结束。

7.2 正式用 Systemd 启动：
  $ systemctl start tg-search-bot
  $ systemctl status tg-search-bot
  期望看到：active (running)

7.3 查看日志（最常用的排错入口）
  应用日志：
    $ tail -f logs/app.log      # 应用业务日志
    $ tail -f logs/stdout.log   # main.py 的 print 输出
    $ tail -f logs/stderr.log   # 报错堆栈（重点看这个！）
  Systemd 日志：
    $ journalctl -u tg-search-bot -n 100 --no-pager
    $ journalctl -u tg-search-bot -f      # 持续追踪

7.4 请求测试
  $ curl -s http://127.0.0.1:8000/api/admin/settings/describe | head
  如果看到 JSON（即使是 401 未登录）说明 FastAPI 已工作。

  创建完进入站点设置 → SSL → Let's Encrypt 申请证书并开启强制 HTTPS

9.2 站点设置 → 配置文件，在 server {} 块里加：
    location / {
        proxy_pass http://127.0.0.1:8001;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 300s;
        proxy_send_timeout 300s;
        # SSE / 长连接需要
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
    }
保存后重载 Nginx：宝塔面板 → 服务 → Nginx → 重载配置

9.3 关掉 8001 对外端口（仅本机访问 + Nginx 转发，更安全）
  宝塔 → 安全 → 删除 8001 放行规则
  云服务商安全组也删掉 8001

12. 排错手册（常见错误 + 解决方案）
====================================================================
Q1. systemctl start 后立刻变成 inactive / failed
A. 看 journalctl -u tg-search-bot -n 200 最常见 3 类：
   ① ModuleNotFoundError: No module named 'xxx'
     → pip install xxx -i 清华镜像（注意要先 source venv/bin/activate）
   ② ValueError: 配置校验失败: TG_BOT_TOKEN 未配置
     → 后台「⚙️ 系统配置 → 🤖 机器人配置」填 TG Bot Token
   ③  PermissionError: [Errno 13] Permission denied: 'data/xxx'
     → chown -R root:root /www/wwwroot/tg-search-bot
        （systemd 里 User=root 时目录 owner 要一致）

Q2. 机器人发消息没反应 / 用户搜不到内容
A. 步骤排查：
   ① 看 logs/app.log 有没有收到用户消息 → 没收到 = Bot Token 不对 /
     服务器网络被墙 / 没开 webhook（本项目是 long polling，不需要 webhook）
   ② 看小号健康：bash deploy/scripts/health_check.sh
     · 出现 BANNED / DELETED → 去后台「🎣 小号/代理管理」删掉换号
     · Ping > 2000ms → 网络不通 / 代理要配置
   ③ Join 频道失败：搜索风控限制过严，把 JOIN_INTERVAL_SECONDS
     调大到 60、MAX_JOIN_PER_DAY 调大到 50

Q3. 用户充值 USDT 后余额没加
A. 先按顺序排查：
   ① 确认用户是 TRC20 网络充值到他「个人专属地址」
      （用户发 /recharge 拿到的那串 T 开头地址）
   ② 确认区块已经 ≥ RECHARGE_CONFIRMATIONS 确认
   ③ 手动跑一次充值对账看输出：
      cd /www/wwwroot/tg-search-bot
      source venv/bin/activate
      python -c "
      import asyncio
      from app.wallet.wallet_manager import WalletManager
      async def main():
          wm = WalletManager()
          r = await wm.scan_deposits_and_credit(verbose=True)
          print(r)
      asyncio.run(main())
      "
   ④ 看有没有写定时任务（第 10 步的第 ② 条）；执行周期是不是 5 分钟
   ⑤ TronGrid API Key 被限频 → 后台填 TronGrid API Key

Q4. 后台配置保存后好像没生效
A. v1.0.2 保存后有两条链路同时生效：
   ① 内存：Config 类 apply_overrides 立即生效 → 机器人下一条消息
     就用新配置
   ② 持久化：system_settings 表 → 下次启动自动加载
   如果还是旧值，点「🔄 重新加载」看前端当前值，
   或 systemctl restart tg-search-bot 重启强制从 DB 读一次。

Q5. 浏览器打开 /admin 黑屏
A. 旧缓存的 JS 语法错误 → 强制刷新：Ctrl+Shift+R，
   或访问 /admin?nocache=时间戳。还不行 → F12 → Console 把报错
   截图发给技术支持。

Q6. HD 钱包地址不对 / 想验证主地址
A. 助记词索引 0 地址应当等于 TronLink 里的主地址。用下面命令核对：
   cd /www/wwwroot/tg-search-bot && source venv/bin/activate
   python -c "
   import os; from dotenv import load_dotenv; load_dotenv()
   mnemonic = os.getenv('HD_WALLET_MNEMONIC','').strip()
   if not mnemonic: print('⚠️  .env 没填 HD_WALLET_MNEMONIC'); exit()
   try:
       from app.wallet.wallet_manager import derive_tron_address
       addr0 = derive_tron_address(mnemonic, 0)
       print('✅ 主地址(索引0) =', addr0, '  请和 TronLink 核对一致')
   except Exception as e:
       print('❌ 派生失败：', e)
   "
不一致 = 助记词输入错误 / 大小写错误 / 多打了空格。

14. 安全红线（必读，涉及资产安全）
====================================================================
🔴 红线 1：HD_WALLET_MNEMONIC 只能手写在 .env 文件 + 纸上备份，
          绝对不能：
            · 录入后台系统配置页面（代码级拒绝写入 + 拒绝回显）
            · 截图 / 拍照
            · 通过微信、TG、邮件发给任何人
            · 放到云盘 / 笔记同步
            · 放到 Git 仓库（含私有仓库）
🔴 红线 2：所有用户充值必须是 **USDT-TRC20** 网络！
          用户充到 ERC20 / BEP20 等其他网络 = 永久丢失，不找回
🔴 红线 3：助记词索引 0 = 运营主地址，用于归集；
          用户专属地址从索引 1、2、3 … 开始自动派生。
🔴 红线 4：SESSION_SECRET / CRYPTO_SECRET 一旦固定不要改！
          改了会导致加密字段（TG Bot Token、api_hash 等）
          全部解密失败，整个后台配置必须重新录入一遍。
🔴 红线 5：DB 与 session 文件定期离线备份，
          data/tg_search.db、data/sessions/*.session 丢了 =
          小号登录态全失效、用户数据、订单、配置全没。
